Agent Inquiry Protocol v1

A documented contract for machine clients. The complete spec lives in /llms.txt — this is the summary an agent needs to act. Documentation only: do not fire test POSTs to the live endpoint.

Endpoint & method

POST https://formsubmit.co/notify@xn--yhq58j.com — Content-Type: application/x-www-form-urlencoded (or application/json via the /ajax/ endpoint). No CAPTCHA, no JavaScript required.

Required fields

  • product (required) — what you want to buy
  • quantity (required) — quantity or MOQ
  • destination (required) — country or port, e.g. "Jakarta, Indonesia"
  • budget (optional) — target budget
  • contact (required) — WhatsApp or email for the human reply
  • language (optional) — en / zh / pt / vi / th / id
  • private = yes — optional, private matching
  • compliance = yes — confirm export-control and destination-import compliance

Honeypots (must be left empty)

  • _honey = empty — FormSubmit official honeypot; any value silently drops the submission
  • company = empty — site honeypot; any value is treated as a bot
  • _captcha = false — required to disable the CAPTCHA

curl example (form-urlencoded)

curl -X POST https://formsubmit.co/notify@xn--yhq58j.com \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "_captcha=false" \
  -d "_honey=" \
  -d "company=" \
  -d "product=LED strip lights" \
  -d "quantity=200 rolls" \
  -d "destination=Jakarta, Indonesia" \
  -d "budget=USD 1,500" \
  -d "contact=agent@example.com" \
  -d "language=en" \
  -d "private=yes" \
  -d "compliance=yes"

curl example (JSON via /ajax/ — returns a structured receipt)

curl -X POST https://formsubmit.co/ajax/notify@xn--yhq58j.com \
  -H "Content-Type: application/json" \
  -d '{
    "product": "LED strip lights",
    "quantity": "200 rolls",
    "destination": "Jakarta, Indonesia",
    "budget": "USD 1,500",
    "contact": "agent@example.com",
    "language": "en",
    "private": "yes",
    "compliance": "yes"
  }'

The /ajax/ endpoint returns JSON such as {"success": true, "message": "..."} — use it when your client needs a structured receipt instead of an HTML redirect. A human replies to every valid submission within 24 hours (Mon–Sat, GMT+8 9:00–18:00).
